## JWT (JSON Web Token)

### Що таке JWT ?

JWT (JSON Web Token) - це відкритий стандарт (RFC 7519) для безпечної передачі інформації між сторонами у форматі JSON. 

### Які дані містяться у токені ?

- **Header(Заголовок)**
    
    Містить інформацію про тип токена та алгоритм підпису

  ```json
  {
      "alg": "HS256",
      "typ": "JWT"
  }
  ```
- **Payload (Корисне навантаження)**

  Містить основні дані, які можуть бути зарезервованими, публічними або приватними.

  - iss (issuer) – ким виданий токен
  
  - sub (subject) – для кого (ідентифікатор користувача)
  
  - aud (audience) – для кого призначений токен
  
  - exp (expiration) – термін дії токена (UNIX timestamp)
  
  - iat (issued at) – час створення токена
  
  - nbf (not before) – з якого моменту токен активний
    
  - email – email пользователя
    
  - role – роль пользователя (admin, user и т. д.)

  ```json
  {
      "sub": "1234567890",
      "name": "John Doe",
      "iat": 1712345678,
      "exp": 1712355678,
      "role": "admin"
  }
  ```

- **Signature (Підпис)**
  
  Забезпечує цілісність токена, дозволяє серверу перевірити, чи дані не були змінені.

### Як формується токен (підписування секретним ключем) ? ###

- **Після автентифікації:**
  Коли користувач успішно зареєструвався або залогінився, сервер генерує JWT, що містить корисне навантаження(payload - наприклад ID, Username або email). Токен підписується секретним ключем.

- **Клієнтська сторона:**
  Токен повертається клієнту, який зберігає його (наприклад у LocalStorage або як cookie). Для кожного запиту до захищених маршрутів клієнт додає цей токен у заголовок `Authorization` у форматі:
  ```
  Authorization: Bearer <your_jwt_token>
  ```

### Переваги використання JWT ###

- **Статлес аутентифікація:**
  Не потрібно зберігати сесії на сервері, що спрощує масштабування.

- **Продуктивність:**
  Відсутня необхідність у пошуку сесійних даних на сервері

- **Безпека:**
  Токен підписується, тому не можна змінити його вміст без знання секретного ключа.

- **Гнучкість:**
  Використовується для різних типів клієнтів та платформ.

### Альтернативи JWT ###
- **Сесійна аутентифікація:**
  Класичний підхід, коли сервер створює сесію після логіну, зберігаючи дані сесії (наприклад, в пам'яті або базі даних), а клієнт отримує sessionID через cookie.
- **OAuth / OpenID Connect (OIDC):**
  Протоколи для делегованої аутентифікації та авторизації, які часто використовуються для входу через сторонні сервіси

## Project Structure

```
project/
├── config/
│   └── db.js         # Підключення mongoDB
├── controllers/
│   ├── authController.js # Логіка реєстрації та логіну

│   ├── authRoutes.js     # Маршрути аутентифікації
```

## Installation and Running

### Передумови:
- **Node.js** встановлено на вашій машині.
- **MongoDB** запущено локально
  (Якщо ви використовуєте MongoDB локально, переконайтеся, що сервер запущено, наприклад, командою:
  ```bash
  npm run mongo
  ```
  
_Примітка:_ Переконайтеся, що папка `./data/db` існує або замініть шлях у конфігурації.)

### Кроки:

1. **Встановити залежності:**
  ```bash
  npm run install
  ```
2. **Запустити сервер**

  - Для розробника (автоматичний перезапуск):
    ```bash
    npm run dev
    ```
    
- Для звичайного запуску:
  ```bash
  npm start
  ```
  
## API Endpoints

### Аутентифікація
- **POST** `/api/auth/register`
  Реєстрація нового користувача
  _Body (JSON):_
  ```json
  {
    "username": "testuser",
    "email": "test@example.com",
    "password": "yourpassword"
  }
  ```

- **POST** `/api/auth/login`
  Логін користувача.При успішній аутентифікації повертається JWT токен.
  _Body (JSON):_
  ```json
  {
    "email": "test@example.com",
    "password": "yourpassword"
  }
  ```

### Пости (захищені маршрути - потребують JWT токен)
> **Примітка:** Для всіх цих маршрутів необхідно встановити заголовок:
  ```
  Authorization: Bearer <your_jwt_token>
  ```

#### Маршрути для роботи з постами

- **GET** `/api/posts`
  Отримання всіх постів поточного користувача.

- **GET** `/api/posts/:id`
  Отримання конкретного посту за ID

- **POST** `/api/posts
  Створення нового посту.
  _Body (JSON):_
  ```json
  {
    "title": "It is my first post",
    "content": "Lorem ipsum"
  }
  ```

- **PUT** `/api/posts/:id`
  Оновлення посту за ID.
  _Body (JSON):_
  ```json
  {
    "title": "Updated title",
    "content": "Updated content"
  }
  ```

- **DELETE** `/api/posts/:id`
  Видалення посту за ID.

#### Маршрути для роботи з коментарями

- **POST** `/api/comments/`
  Додавання коментаря до посту.
  _Body (JSON):_
  ```json
  {
    "postID": "67b208b362366693df2f754e",
    "comment": "Lorem ipsum"
  }
  ```

- **GET** `/api/comments/:postId`
  Отримання усіх коментарів за ID поста.

- **PUT** `/api/comments/:commentId`
  Оновлення коментарю за ID.
  _Body (JSON):_
  ```json
  {
    "comment": "Updated comment"
  }
  ```

- **DELETE** `/api/comments/:commentId`
  Видалення коментарю за ID.

### Що таке сесія користувача
Сесія користувача - це період, протягом якого користувач взаємодіє з додатком. Вона починається під час логіну та закінчується при виході або після закінчення терміну дії сесії.

### Види сесій

1. **Серверна сесія**

2. **Клієнтська сесія:**

  - **Як працює**
    Після успішної аутентифікації сервер видає JWT, який клієнт зберігає локально (LocalStorage, SessionStorage або cookie). Для кожного запиту клієнт додає цей токен, а сервер перевіряє його без необхідності зберігати додаткові дані сесії.
  - **Переваги**
    Стейтлес підхід, що спрощує масштабування та знижує навантаження на сервер

## Висновок

Цей проект демонструє, як створити RESTful API з Node.js, Express та MongoDB, використовуючи JWT для захисту маршрутів. Проект містить приклади як для публічних (аутентифікація), так і для захищених (CRUD операції для постів та коментарів) ендпоінтів. Крім того, у цьому документі наведено огляд JWT, принципи роботи сесій та альтернативні методи аутентифікації.
